# Human interface and Thai writing

Use this guidance for screens, interactions, emails, notifications, labels, and errors.

## Voice

- Write concise, natural Thai used by an administrative team. Prefer `สร้างการประชุม`, `บันทึกฉบับร่าง`, and `ส่งให้ตรวจทาน` over technical or promotional phrasing.
- State what happened and what the person can do next. Example: `บันทึกร่างรายงานแล้ว`.
- Name the actual object in destructive confirmation text. Avoid vague `ดำเนินการต่อหรือไม่`.
- Do not use AI-themed claims, sparkle decoration, generated-sounding advice, chatty filler, or inflated productivity language unless an AI feature is explicitly requested.

## Interaction

- Match the user's work sequence. Use status, owner, due date, and next action rather than abstract metrics.
- Ask only for information needed at the current step; allow optional details later.
- Keep primary actions visually stable: create at the page header, save/submit at the lower right of a form, secondary cancel beside it.
- Show exact dates, people, document names, and last-update times where they help someone decide.
- Never make approval, publication, sharing, invitations, or permission changes implicit.

## Visual character

- The interface is calm, administrative, and contemporary: light blue-gray canvas, white documents and tables, navy structure, and clear blue primary actions. Reserve amber or red for states that genuinely need attention.
- Favor borders, spacing, typography, and small status fills. Avoid gradients, glass-heavy surfaces, excessive charts, oversized rounded cards, and decorative blobs.
- Use Lucide icons as supporting cues, not as substitutes for important labels.
- Ensure layouts work at 360 px without hiding the next required action.
